## 1. 技术路线选型：RealWorld vs Ghost

| 维度 | RealWorld 规范路线 | Ghost 完整产品路线（**本项目采用**） |
|---|---|---|
| 形态 | 一套博客业务 **API 规范**（Conduit），非可运行成品 | 成熟可运行的 **Node.js 开源博客产品**（含前台/后台/编辑器/会员） |
| 是否要自研底层 | 需自实现认证、数据库、编辑器等全部核心 | 复用成熟核心，**不重写**认证/数据库/编辑器 |
| 二次开发落点 | 从零搭建（工程量在“造轮子”） | 修改边界限定在 **自定义主题 + Content API 调用 + 上层扩展** |
| 教学目标 | 适合“按规范实现一套系统”的工程训练 | 适合“在真实开源产品上做受控二次开发”的工程训练 |
| 交付可运行软件 | 需大量时间，2 学时内很难达成 MVP | 基线即可跑，2 学时内可完成注册/写作/评论/搜索主线 |

**结论**：采用 **TryGhost/Ghost（MIT）** 作为基线项目。核心思想 —— *不重写底层核心能力，基于成熟开源 Ghost 做二次开发*，把学生本人的工作集中在可独立交付、可回滚的主题与上层扩展上，并保留完整 Git 证据区分“上游功能”与“本人开发功能”。

## 2. 为什么修改“主题/上层扩展”而不是“Ghost 核心源码”

1. **可持续升级**：Ghost 内核（core）随上游迭代，若直接改内核，每次 `ghost update` 都会被覆盖、且无法合回上游，形成长期维护债务；而主题与扩展挂在稳定接口（Content API、handlebars 渲染管线）上，升级内核不会冲掉二次开发成果。
2. **许可与上游友好**：改动集中在独立目录，许可证边界清晰（NOTICE 可如实标注），也便于未来向社区上游合入。
3. **实验可验证性**：评审可明确区分“哪些来自上游、哪些是本人开发”，用 Git diff 就能界定工作量，避免“改了颜色也算二次开发”的模糊。

## 3. 固定版本记录（基线锁定）

| 组件 | 版本 | 说明 |
|---|---|---|
| Ghost（基线应用） | `6.62.0` | 镜像 `ghost:6.62.0`（容器内 `current/package.json` 实测确认） |
| Node.js | `v22.x`（宿主/镜像内 LTS） | 满足 Ghost 6 要求 |
| 数据库 | SQLite（`content/data/ghost.db`） | 零配置，便于个人实验与备份恢复演示 |
| 运行方式 | **Docker Compose**（`runtime/docker-compose.yml`） | Ghost 官方镜像 + Mailpit 本地收信；`docker compose up -d` 一键起停 |
| 邮件 | Mailpit（SMTP 1025 / Web 8025） | 本地接收会员注册/登录验证邮件，magic link 可离线获取 |

> 环境结论：Ghost **官方不支持原生 Windows**（依赖 native 模块编译需 VS 工具链，实测安装失败）。本机采用 Docker 方案，符合 Ghost 官方对 Windows 的推荐做法，并让 README 在“全新电脑”上可一键复现。
> 规则：主分支 main 始终对应当前锁定版本 `6.62.0`；后续版本变更必须新建分支并记录变更原因。

## 4. 六条验收场景（Acceptance Scenarios）

每条均需在 **本地可运行软件** 上连续演示，前置条件、操作、期望结果记录在 `tests/acceptance.md`。

- **AS-1 管理员写作发布**：管理员登录后台 → 新建文章并绑定至少 1 个标签 → 发布 → 前台可浏览该文章。失败态：空标题/无内容给友好提示。
- **AS-2 账号体系**：存在管理员与普通会员两类账号；新访客可注册为普通会员并登录。
- **AS-3 会员评论**：已登录会员在文章详情页提交评论 → 评论可见；**空评论不允许提交**并给出提示。权限：匿名访客不能评论（需登录引导）。
- **AS-4 搜索**：关键词可命中标题/正文并返回结果；无命中时给出“未找到相关文章”的无结果提示（不报错）。
- **AS-5 全站可用与响应式**：首页 / 文章列表 / 详情 / 标签页 / 登录 / 评论 / 搜索全部可用；桌面与移动端窄屏布局均正常。
- **AS-6 数据持久化与恢复**：重启服务后文章/评论/账号数据不丢失；后台可导出数据，导入后数据可恢复验证。

## 5. 风险清单与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Ghost 6 主题 API 与本机 Node 版本兼容 | 主题无法渲染 | 固定 Node 22；主题改造前先跑通官方主题基线 |
| 国内网络下载 npm 依赖慢 | 安装超时 | 项目级 .npmrc 走 npmmirror 镜像；分步安装 |
| 首次安装失败 / 端口 2368 被占用 | 无法启动 | 以官方 `ghost install local` 标准流程为准并记录错误日志；可换端口 |
| 数据库文件被误提交 | 敏感数据泄露 / Git 污染 | .gitignore 严格排除 *.db、content/、密钥、日志 |
| 桌面与移动端差异 | 移动端布局崩 | 主题开发阶段用浏览器窄屏模式逐页检查 |
